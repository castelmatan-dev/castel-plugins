# מבנה הנתונים

## Drive

```
<שורש>/                              ברירת מחדל: "מוצרים". אם המשתמש או הבקשה מציינים שורש אחר (למשל "מוצרים-בדיקה"), עובדים רק בו
├── _רשימת מוצרים.json                מקור האמת של הרשימה
├── _ויקי/products-<slug>.md          עמוד ויקי לכל מוצר
└── <שם בעברית> - <מותג> <דגם>/        תיקייה לכל מוצר
    ├── <סוג המסמך>.<סיומת>            חשבונית / קבלה / אישור הזמנה / תעודת משלוח, לפי מה שכתוב על המסמך
    ├── תעודת אחריות.<סיומת>          אם יש (גם תעודה רשמית שהורדה מאתר היצרן או היבואן)
    ├── הוראות - <מקור>.<סיומת>        PDF יצרן, או צילומי עמודים
    └── סיכום שימוש ואחזקה            Google Doc, לפי assets/usage-doc.md
```

- שורש חסר → יוצרים אותו. `_רשימת מוצרים.json` חסר → מתחילים מ-`assets/products.example.json` (רשימה ריקה).
- **שם קובץ = סוג המסמך כמו שכתוב עליו.** קבלה היא לא חשבונית מס, ותעודת משלוח היא לא חשבונית. כשמחפשים בעוד שנה "החשבונית של X", צריך לדעת מיד מה יש ביד.
- **slug:** מזהה קצר באנגלית, אותיות קטנות ומקפים: `<brand>-<type>` (למשל `bosch-washer`). אם תפוס, מוסיפים את הדגם.

## איך עובדים עם הרשימה

הרשימה יושבת ב-Drive, והסקריפט עובד על קובץ מקומי. לכן בכל כתיבה:
1. מורידים את `_רשימת מוצרים.json` לקובץ זמני.
2. מריצים את הסקריפט על הקובץ הזמני.
3. מעלים את הקובץ המעודכן בחזרה (עדכון אותו קובץ ב-Drive, לא קובץ חדש).

בקריאה בלבד (find, status) מספיקים שלבים 1–2.

## פקודות הסקריפט

```bash
S=<תיקיית הסקיל>/scripts/products.py
python3 $S init     --file list.json                       # רשימה ריקה, אם אין
python3 $S validate --file list.json                       # בדיקת תקינות
python3 $S find     --file list.json "מכונת כביסה"          # חיפוש גמיש: שם, מותג, דגם, כינוי, slug
python3 $S status   --file list.json [--id <slug>] [--today YYYY-MM-DD]
python3 $S add      --file list.json --record rec.json     # מוסיף; מחשב warranty_until; עוצר על כפילות
python3 $S add      --file list.json --record rec.json --update   # מעדכן רשומה קיימת (רק באישור המשתמש)
python3 $S calc     --start 2025-12-01 --months 12        # תאריך תפוגה + ימים שנותרו, לפני שיש רשומה (לכרטיס האישור)
```

- כל הפלט הוא JSON ב-stdout. שגיאה → הודעה ב-stderr וקוד יציאה שאינו 0.
- `add` מחזיר קוד **2** כשיש כפילות (אותו `id`, אותו מספר סידורי, או אותו ספק + מספר חשבונית). במקרה כזה לא מוסיפים: מציגים למשתמש את הרשומה הקיימת ושואלים אם לעדכן.
- `add` ו-`validate` דוחים רשומה עם קישור שיש בו כתובת מייל או `authuser=`. מנקים את החלק הזה מהקישור (למשל `https://mail.google.com/mail/u/0/#all/<id>`), לא עוקפים.
- `status`: `valid` בתוקף · `expiring` פחות מ-60 יום · `expired` פגה · `unknown` לא ידוע. באחריות מפוצלת מוחזר גם `parts`, עם סטטוס לכל חלק.
- **כל תאריך שמופיע בתשובה למשתמש** (תפוגה, "נשארו X ימים") מגיע מפלט של `calc` או `status`, כולל בכרטיס האישור, לפני שיש רשומה.

## הרשומה

שדות חובה: `id`, `name_he`. כל השאר רשות, וחסר = לא ידוע (לא מנחשים).

| שדה | משמעות |
|---|---|
| `id` | slug |
| `name_he` | שם בעברית ("מכונת כביסה") |
| `brand`, `model` | מותג ודגם, כמו שכתוב על המוצר |
| `serial_no`, `barcode` | מספר סידורי וברקוד. מרכז שירות שואל קודם כל על המספר הסידורי |
| `aliases` | כינויים שהמשתמש משתמש בהם ("המכונה", "הפלנצ'ה") |
| `vendor`, `invoice_no`, `order_no`, `purchase_date` (YYYY-MM-DD) | רכישה. `invoice_no` הוא מספר המסמך, גם אם זו קבלה |
| `purchase_doc_type` | `invoice` · `receipt` · `order` · `delivery_note`: מה המסמך שיש ביד |
| `delivery_date`, `delivery_note_no` | אספקה, אם יש תעודת משלוח |
| `price_ils` | מחיר כולל מע"מ, מספר |
| `payment` | אמצעי תשלום בלי מספרים (למשל "אשראי", "PayPal") |
| `warranty_start` | מאיזה תאריך האחריות נספרת, אם לא מתאריך הרכישה (למשל "ממועד האספקה") |
| `warranty_months` | תקופת האחריות הכללית. הסקריפט מחשב ממנה את `warranty_until` |
| `warranty_until` | תפוגה. אם ידועה במפורש (כתובה בתעודה), היא גוברת על החישוב |
| `warranty_parts` | אחריות מפוצלת: רשימה של `{"part": "מבערים", "months": 300}` (או `until`), ו-`note` לפי הצורך. הסקריפט מחשב `until` לכל חלק. התקופה הכללית ("שאר החלקים") נכנסת ל-`warranty_months` |
| `warranty_conditions` | תנאים לתוקף האחריות, כמו שכתוב: רישום, חשבונית, התקנה בידי טכנאי מוסמך |
| `warranty_source`, `warranty_source_url` | מאיפה תנאי האחריות: `document` (מסמך של המשתמש) · `official_web` (אתר היצרן או היבואן הרשמי, חובה קישור) · `user` (המשתמש אמר) |
| `warranty_provider`, `service_contact` | מול מי, ואיך יוצרים קשר לשירות |
| `manual_source` | `manufacturer_pdf` · `photos` · `none` |
| `drive_folder_url`, `invoice_url`, `warranty_doc_url`, `manual_url`, `doc_url` | קישורים. בלי מייל ובלי `authuser` |
| `wiki` | `products-<slug>.md` |
| `vector_sources` | רק במצב מורחב: ה-`source_id`-ים של המוצר במאגר הווקטורי (למשל `samsung-tv-manual`) |
| `status` | `active` · `retired` (מוצר שיצא משימוש. לא מוחקים) |

תאימות: אם ברשימה קיימת יש שדות נוספים שלא מופיעים כאן, משאירים אותם כמו שהם.
